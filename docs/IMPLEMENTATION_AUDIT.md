# Implementation audit

## Repository structure

The repository is a Rust workspace with three members:

- `crates/ogunedo-core`: `no_std + alloc` compatible relation, parameter registry, matrix expansion, NTT arithmetic, digests, and tests.
- `program`: minimal SP1 guest that reads a `PublicStatement` and `Witness`, calls `verify_relation`, and commits `PublicValues`.
- `script`: SP1 host CLI for generating fixtures, native checking, execution, proving, verification, and verification-key printing.

Supporting files include GitHub Actions, Python reference checks, deterministic fixtures, release scripts, dual licences, security policy, and protocol documentation.

## Implemented functionality

- Canonical public statement digest with SHA-256 domain separation.
- Canonical relation digest.
- Canonical parameter digest committed in `PublicValues`.
- Deterministic rejection-sampled matrix expansion.
- Negacyclic NTT multiplication with schoolbook cross-checks.
- Registered development and draft engineering parameter sets.
- Coefficient-bound, norm-bound, target-length, target-canonicality, witness-length, protocol-version, and parameter-ID checks.
- SP1 guest crate that invokes the same core verifier as the native host.
- CLI paths for SP1 execute/prove/verify, subject to SP1 host support.
- Offline source validator and independent Python arithmetic model.

## Missing or incomplete functionality

- The determinant-one Keller compiler is not implemented in this source tree. It remains a research layer and must not be advertised as part of the executed v1 SP1 proof relation.
- The SP1 host CLI could not be built locally on this Windows `gnullvm` host because `sp1-jit` requires POSIX APIs.
- No Groth16 proof has been generated.
- No production parameter set is approved.
- No estimator evidence is included for the draft module-ISIS profile.
- No fuzz harnesses are present yet.

## Compile blockers

`cargo check -p ogunedo-cli --locked` and full workspace checks fail in the upstream `sp1-jit` dependency on Windows:

```text
unresolved import std::os::fd
unresolved imports libc::ftruncate, madvise, sem_open, shm_open, ...
```

The core crate and SP1 guest crate both compile locally. The host proving CLI should be built and exercised in the Linux GitHub Actions environment.

## Correctness repairs made

- The draft v1 norm bound was corrected from `18432` to the requested canonical bound `10240`.
- `PublicValues` now commits the registered parameter digest as well as statement and relation digests.
- Exact v1 relation and parameter digest values are frozen by Rust tests.
- `script/build.rs` now remaps the SP1 guest build Cargo home to `/root/.cargo`, eliminating machine-specific Cargo registry paths from the guest ELF and restoring byte-for-byte cross-machine reproducibility for the submitted compressed proof.
- `ogunedo verify` now supports explicit proof SHA-256, proof byte length, statement SHA-256, proof mode, and vkey bindings; it also rejects symlinked proof/statement inputs and fails malformed artifacts before expensive SP1 setup when possible.
- The Python validator now works on Python 3.10 through `tomli` and uses `sys.executable` for subprocess checks.
- The validator now excludes `.git`, `target`, `dist`, `artifacts`, `proofs`, and `benchmarks` from source structured-file counting.
- GitHub Actions checkout was changed from the invalid `actions/checkout@v6` reference to `actions/checkout@v4`.

## Security-sensitive code

- `crates/ogunedo-core/src/relation.rs`: accepts or rejects the statement/witness pair and emits public values.
- `crates/ogunedo-core/src/matrix.rs`: deterministic public matrix expansion.
- `crates/ogunedo-core/src/ntt.rs`: ring multiplication.
- `crates/ogunedo-core/src/digest.rs`: statement, relation, and parameter binding.
- `program/src/main.rs`: guest boundary and committed public values.
- `script/src/main.rs`: host proof verification, proof public-value decoding, and statement binding.

## Documentation/code disagreements

The attached release request specified `||w||_2^2 <= 10240`; code used `18432`. The source has been updated to `10240`, and docs/tests now match.

Earlier conversation-level digest constants did not match the code's domain-separated SHA-256 derivations. Because v1 is unreleased, the coherent implementation values were selected and frozen:

```text
relation_digest              = 12ca32d006589f7fa7b3edaa4c1c19d3940661ae8528917738878dfe40d88feb
development_parameter_digest = bbf88444329630d91a6cade2f16681dcdd87eefc59e1b652ee799a1e77da97fe
draft_parameter_digest       = e8c8d261c2d5082a300d241434465245371db7c68b0d5df8e3a05f233af19611
```

## Fixture status

The development fixtures are internally valid and regenerated by the independent Python reference implementation. The draft-profile validation uses deterministic arithmetic checks but does not provide a production security proof or trapdoor distribution.
